# reports/ - аналитика и отчёты

Приложение без собственных моделей: только расчёты и отображение. Сводки -
в `queries.py` (`month_report(year, month, owner)`, `year_report(year, owner)`),
страницы - в `views.py`, данные для графиков передаются в шаблон через
`json_script`. Считаются только данные владельца.

- `home` (`/`) - обзорная страница: текущий месяц и цели покупок;
- `/reports/` и `/reports/<год>/<месяц>/` - отчёт за месяц: доход,
  "отложить", столбцы "Бюджет / Траты / Остаток" по категориям
  (остаток = бюджет − траты: "+" зелёным, минус красным при перерасходе),
  процент исполнения; график "бюджет и траты по категориям";
- `/reports/<год>/` - итоги года: таблицы по месяцам и по категориям,
  графики "бюджет и траты по месяцам" и "структура трат", кнопка возврата
  в месячный отчёт (вернуться в тот месяц, откуда пришли);
- Chart.js подключён локально (`static/js/vendor/chart.umd.min.js`,
  версия и sha256 - в README рядом), отрисовка - `static/js/reports.js`;
- PDF-отчёты (`reports/pdf.py`): кнопки "Скачать PDF" на экранах
  месяца и года, эндпоинты `/reports/<год>/<месяц>/pdf/` и
  `/reports/<год>/pdf/`; вёрстка - WeasyPrint (шрифт DejaVu Sans;
  в Docker - `fonts-dejavu-core`), графики - matplotlib (в круговой
  топ-8 категорий + "Прочее"); файлы сохраняются атомарно в
  `media/reports/<id владельца>/<год>-<месяц>.pdf` и `<год>.pdf` -
  у каждого пользователя свои, публично media не раздаётся.
  Matplotlib и WeasyPrint импортируются лениво - при обычных запросах
  не грузятся; если их нет в образе, страница подсказывает пересобрать его.
